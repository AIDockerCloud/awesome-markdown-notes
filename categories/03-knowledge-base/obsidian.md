## 一句话定位

本地文件夹（vault）之上的知识库：双向链接、图谱和庞大的社区插件生态。

## 四字段判定 [事实]

| 字段 | 内容 | 核实来源 |
| --- | --- | --- |
| 协议 | 闭源；个人使用免费，Sync / Publish 为付费附加服务 | 主清单 |
| 平台 | Windows / macOS / Linux / iOS / Android | 主清单 |
| 数据真源 | vault 内的 `.md` 文件（本地文件夹） | 主清单 |
| AI 形态 | 无内置 AI，靠社区插件接入 | 主清单 |

## 要点 [事实]

- 入口：https://obsidian.md/help/official-site
- 本层解决的是「笔记之间怎么连、怎么查」，不是单文件手感；主清单明确说把它当 Typora 平替会错位 —— 迁移成本、数据格式和日常操作完全是另一回事。
- 正文是 vault 里的标准 `.md`，但应用本身闭源；Sync / Publish 是与正文存储无关的独立付费服务。
- 插件生态是本条的结构性特征，也决定了 AI 能力来自社区而非内置。

## 归类理由与边界 [推断]

- 与单文件编辑器层的分界：是否先建 vault、是否以双链 / 图谱组织多篇笔记。
- 与速记层的分界：它要求先有标题、文件夹和结构，不是「想到就记」。
- **跨类指回**：官方插件 obsidian-opentodo（[OpenTodo](../05-task-management/opentodo.md)）把 Obsidian 当作操作入口，但任务仍存 OpenTodo 服务器；[TaskNotes](../05-task-management/tasknotes.md) 与 [taskquence](../05-task-management/taskquence.md) 反过来把任务直接存成 vault 里的笔记。三者真源完全不同，选错等于选错真源。
