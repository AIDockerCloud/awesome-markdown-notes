# 项目核心定义 (PROJECT.md)

## 项目定位与宗旨

- **项目名称**：Awesome Markdown Notes（仓库名 `awesome-markdown-notes`）
- **核心定位**：面向 AI 与 Agent 时代的 Markdown 编辑器 / 笔记软件**精选清单**。以 Typora 为判定基准，按用途分层收录，不把单文件编辑器、知识库、速记和任务管理混在一张表里比。
- **判断视角**：新项目的差异点不在「排版更好」，而在 **AI、MCP 与能否被 agent 读写**；清单因此把「数据真源存在哪一端」当作分类依据，而非功能多寡。
- **唯一对外产物**：根目录 `README.md`。

## 核心目标 (Scope)

- 按用途分层维护 8 个分区：判定基准（Typora 本体）、单文件编辑器、AI 与 Agent 时代的新编辑器、知识库与笔记系统、速记与自托管笔记、任务管理 / Todo、已有的同类清单与目录、收录标准与维护方式。
- 每条只记可判定的结构性信息：**协议、平台、数据存哪（裸 `.md` / 自有数据库 / 服务器）、AI 形态（内置 / 插件 / MCP / 无）**；没核实到的字段就不写。
- 收录通过门槛的活跃项目并持续验活：把停更、归档、改协议的旧条目标注或移出。
- 相邻品类（任务管理、速记）单独成节，并写清数据真源在哪一端。
- 维护固定的 GitHub Topics：`markdown`、`note-taking`、`awesome-list`、`ai`、`markdown-editor`。

## 明确非目标 (Non-Goals)

- 不做软件本体、插件、构建工具、站点或运行时代码；仓库里没有产品源码。
- 不做投票排名、星数排行或「最佳 N 款」结论，不做逐款实测评分。
- 不记录价格、具体版本号、发布日期等易过期信息；价格以官网为准。
- 不收纯 fork、已归档、无正式 Release 的概念项目。
- 不因某笔记软件附带任务功能就把它写成任务管理工具，反之亦然；不设双真源。
- 不暗示与任何被收录产品的官方关联、背书或赞助。

## 不得违反的硬约束 (Hard Boundaries)

1. **免责声明不可弱化**：README 开头必须保留「与 Typora 无关联、未获其背书或赞助；Typora 是其权利人的商标，提及仅为指名性说明比较对象与判定基准」。
2. **四字段可判定**：任何条目若无法判定协议 / 平台 / 数据真源 / AI 形态中的关键事实，只能记入候选，不得进入正表。**人类明确指示的批量转正为例外**：2026-11-10 的 8 款按 DEC-006 收录，四字段一律显式写 `—（未核实）`，不猜测填充。
3. **单一主分区**：同一软件只在一个分区写完整介绍，跨界的用一句话指回主条目，禁止双头维护（双头必然分叉）。
4. **入选门槛**：有正式 Release 且近 6 个月内有提交；纯 fork、已归档、无 Release 的概念项目不收。**闭源且无公开仓库的产品（如 Typora）以官网发布页 / 更新记录判定活跃度，不以 GitHub 提交判定（DEC-007）**。DEC-006 的人类确认收录为例外，morrow（仅测试预览版）、tolaria（仅 Alpha）、虎鲸笔记（源码长期不更新）须在首轮联网核实中复核门槛；TypeOpen 四字段未齐但经人类确认保留正表（DEC-007），不转候选。
5. **结构性信息优先**：每次更新只做两件事 —— 新增过门槛的项目、把停更 / 归档 / 改协议的旧条目标注或移出。
6. **命名中立**：仓库名与主 Topic 不得使用任何单一产品名；正文对具体产品的提及均为指名性比较。
7. **协议与产品解耦**：PCMP 只是人机协同的上下文规范，不得作为内容或运行时依赖写进清单正文。

## 扩展内容结构（2026-11-10 起）

- `categories/`：按主清单同一套分类拆出的独立产品卡片与每类对比清单，用于查看单款详情与该类总体情况。
- `categories/_TEMPLATE.md`：新增软件的统一卡片模板。
- `CHANGELOG.md`：每周进展汇总，也是「对比上一次」的历史日志。
- `categories/_WATCHLIST.md`：巡检观察名单（2026-11-10 由旧定时任务融合进来），16 款含上游地址，**全部已由人类确认转入正表**；与分类对比表并列为检查对象真源。
- 每周定时任务（**周六 09:00**）：对上述两处真源做一次轻量上游核实，逐款与上一次记录对比并写清更新了什么。

### 补充硬约束

8. **不设双真源**：主清单条目与产品卡片描述冲突时，标记差异并核实来源（需求 / ADR / 上游），不静默覆盖任一侧。
9. **对比表 + 观察名单即巡检清单**：新软件须在所属分类 `README.md` 对比表或 `categories/_WATCHLIST.md` 登记一行，才会进入每周核实；名单落在仓库文件里，不写死在定时任务提示词中。
10. **未核实不填充**：四字段判定不了写 `—（未核实）`，并列入卡片「待核实」；严禁猜测或复制宣传语补齐。
11. **每周更新不擅自删条目**：发现停更 / 归档 / 协议变化只标注并提请人类确认，移出正表须人工批准。
12. **链接去版本化**：新增条目的链接优先指向项目主页 / 仓库根地址，不锚定具体 release tag 或 `develop` 分支文件。
13. **历史回填标注来源**：把外部任务的历史产出写进进展记录时，必须标注「历史回填（未联网复核）」与原始文件名；不得当作本轮核实结论，不得把外部报告的主观判断记为 [已确认]。
